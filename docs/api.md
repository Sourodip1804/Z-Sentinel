# Z-Sentinel API Reference

Base URL (local): `http://127.0.0.1:8000`

All endpoints are available with both the standard root paths and the `/api/` prefix for convenience.

Interactive OpenAPI Documentation (Swagger UI): `http://127.0.0.1:8000/docs`  
ReDoc: `http://127.0.0.1:8000/redoc`

---

## 1. Health & Status

### `GET /health` or `GET /api/health`
Returns system status, ML model readiness, MongoDB connection state, and feature contract version.

**Response `200 OK`:**
```json
{
  "status": "online",
  "service": "Z-Sentinel",
  "model_ready": true,
  "model_version": "ZS-PIPE-1.0",
  "mongodb_ready": true,
  "database_mode": "mongodb",
  "paypal_configured": false,
  "genai_configured": false,
  "feature_contract_version": "txn_features_v1"
}
```

## 3. Real-Time Inference & Ingestion

### `POST /predict` or `POST /api/predict`
Evaluates a single transaction, computes fraud probability (0.0 to 1.0), maps it to a risk score (0 to 100), assigns a risk level (`LOW`, `MEDIUM`, `HIGH`) and recommended action (`APPROVE`, `REVIEW`, `BLOCK`), computes local feature contributions, persists the transaction audit record to MongoDB, and returns the response.

**Request:**
```json
{
  "amount": 1450.00,
  "currency": "USD",
  "merchant_category": "online",
  "hour_of_day": 3,
  "device_novelty": 1.0,
  "location_deviation": 0.85,
  "transaction_velocity": 8.0,
  "unusual_time": 1.0,
  "channel": "online"
}
```

**Response `200 OK`:**
```json
{
  "transaction_id": "TXN-9F8C201A4B",
  "source": "api",
  "amount": 1450.0,
  "currency": "USD",
  "merchant_category": "online",

  "fraud_probability": 0.9421,
  "risk_score": 94.21,
  "risk_level": "HIGH",
  "decision": "BLOCK",
  "model_version": "ZS-PIPE-1.0",
  "feature_contract_version": "txn_features_v1",
  "inference_time_ms": 2.45,
```

## 4. Synthetic Simulation

### `POST /simulate` or `POST /api/transactions/simulate`
Generates a realistic synthetic transaction for testing/demonstration, runs it through the full scoring pipeline, and stores it in the audit collection.

**Request (optional body):**
```json
{
  "scenario": "high_amount_online",
  "seed": 42
}
```

Supported Scenarios:
- `legitimate_grocery` (low amount, normal hours, familiar device)
- `high_amount_online` (large online purchase, new device, velocity spike)
- `new_device_travel` (travel booking, device novelty, location deviation)
- `night_velocity` (electronics purchase, late night, elevated velocity)
- `location_spike` (fuel purchase with sharp location deviation)

## 5. Audit Log & History

### `GET /transactions` or `GET /api/transactions`
Paginated query of past evaluated transactions from the database.

**Query Parameters:**
- `page` (integer, default 1)
- `page_size` (integer, default 20, max 100)
- `risk_level` (optional filter: `LOW`, `MEDIUM`, `HIGH`)
- `decision` (optional filter: `APPROVE`, `REVIEW`, `BLOCK`)

**Response `200 OK`:**
```json
{
  "items": [ ... ],
  "total": 42,
  "page": 1,
  "page_size": 20
}
```

### `GET /transactions/{transaction_id}` or `GET /api/transactions/{transaction_id}`
Retrieve a specific transaction audit record by its unique identifier.

## 7. PayPal Webhook (Optional)

### `POST /paypal/webhook` or `POST /api/paypal/webhook`
Optional post-capture webhook receiver.
- Verifies `PAYPAL-TRANSMISSION-SIG` using PayPal Sandbox cert.
- Handles `PAYMENT.CAPTURE.COMPLETED` and `CHECKOUT.ORDER.APPROVED`.
- Enforces idempotency via `paypal_event_id` unique index.
- Returns 503 if PayPal credentials are not configured.
